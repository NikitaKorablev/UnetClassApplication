# Отчет об анализе U-Net модели и Android приложения

## Обзор
Этот отчет анализирует модель сегментации U-Net и Android-приложение, чтобы определить, как обрабатываются предсказания классов, и как обновить Android-приложение для сохранения изображений с осмысленными именами классов вместо общих идентификаторов.

## Анализ U-Net модели

### Определения классов
На основе файлов PROJECT_SUMMARY_RU.md и анализа Python-кода, модель U-Net предназначена для сегментации 6 различных нейронных структур:

1. **Митохондрии** (Mitochondria)
2. **Постсинаптические плотности (PSD)** (Postsynaptic densities)
3. **Везикулы** (Vesicles) 
4. **Аксон** (Axon)
5. **Границы** (Boundaries)
6. **Границы митохондрий** (Mitochondrial boundaries)

### Архитектура модели
Модель использует несколько вариантов U-Net, с Tiny_unet_v3 как наиболее распространенным для мобильного развертывания:
- Вход: одноканальное изображение в оттенках серого
- Выход: 6-канальный тензор, представляющий каждое предсказание класса
- Архитектура основана на кодировщик-декодировщик с пропускными соединениями

### Структура выходных данных предсказания
- Модель выводит тензор формы `[batch_size, 6, height, width]`
- Каждый из 6 каналов соответствует одному из перечисленных выше классов
- После применения функций активации каждый канал содержит вероятностные значения для своего класса

### Реализация предсказания в Python
Python-код (`src/prepare_data.py` строки 422-432) обрабатывает сохранение предсказаний с понятными именами классов:

```python
def saveResultMask(save_path, npyfile, namelist, classnames=None):
    # ...
    for i, item in enumerate(npyfile):
        num_class = item.shape[2]
        for class_index in range(num_class):
            out_dir = os.path.join(save_path,
                                   classnames[class_index] if classnames is not None else str(class_index))
            # ...
            io.imsave(os.path.join(out_dir, "predict_" + namelist[i]), item[:, :, class_index],
                      check_contrast=False)
```

Python-код корректно использует массив classnames для создания директорий с осмысленными именами.

## Анализ Android-приложения

### Текущая реализация сохранения изображений
Android-приложение в настоящее время сохраняет изображения предсказаний классов с общими именами в файле `ImageStitcher.kt` (строки 177-180):

```kotlin
for (i in result.classMasks.indices) {
    val classMaskSaved = ImageSaver.saveImage(result.classMasks[i], resultsDir, "class_${i}.png")
    allClassMasksSaved = allClassMasksSaved && classMaskSaved
}
```

Это приводит к файлам с именами `class_0.png`, `class_1.png`, ..., `class_5.png`, которые не имеют значения для пользователей.

### Поток выполнения кода
1. `MainActivity` вызывает `SegmentationPresenter.startSegmentation()`
2. `SegmentationPresenter` использует `UnetModel` как `ISegmentationUseCase`
3. `UnetModel.startSegmentation()` обрабатывает изображение через:
   - `ImageProcessor` (делит на тайлы и создает тензоры)
   - `InferenceModel` (выполняет инференс PyTorch-модели)
   - `ImageStitcher` (объединяет результаты и сохраняет вывод)
4. `ImageStitcher.saveResults()` сохраняет изображения с общими именами классов

### Необходимые изменения

#### 1. Определение имен классов в Android-приложении
Создать класс или объект, содержащий имена классов, совпадающие с именами в Python-модели:

```kotlin
object ClassNames {
    val NAMES = listOf(
        "mitochondria", 
        "PSD", 
        "vesicles", 
        "axon", 
        "boundaries", 
        "mitochondrial_boundaries"
    )
}
```

#### 2. Обновить ImageStitcher для использования имен классов
Изменить метод `saveResults` в `ImageStitcher.kt` для сохранения каждого маски класса в директории с именем класса:

```kotlin
// Создать директорию для каждого класса
for (i in result.classMasks.indices) {
    val classDir = File(resultsDir, ClassNames.NAMES[i])
    classDir.mkdirs()
    
    val classMaskSaved = ImageSaver.saveImage(
        result.classMasks[i], 
        classDir, 
        "${ClassNames.NAMES[i]}_prediction.png"
    )
    allClassMasksSaved = allClassMasksSaved && classMaskSaved
}
```

#### 3. Обновить компоненты чтения файлов
`DetailActivity` и связанные компоненты, которые читают сохраненные предсказания изображений, должны быть обновлены для чтения из поддиректорий по классам, а не из основной директории результатов.

1. Имена классов должны точно совпадать между Python-моделью и Android-приложением

3. DetailActivity и связанные компоненты должны быть обновлены для работы с новой структурой директорий

## Заключение
Android-приложение в настоящее время сохраняет изображения предсказаний с общими именами (`class_0.png`, `class_1.png`, и т.д.), что затрудняет для пользователей понимание, какое изображение соответствует какой нейронной структуре. Реализовав структуру поддиректорий по классам и осмысленные имена файлов, приложение станет более удобным и интуитивно понятным для использования.
