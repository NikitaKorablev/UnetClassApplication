# Отчет об анализе задачи: Настройка прозрачности классов в U-Net приложении

## Обзор задачи
Требуется добавить новую функцию в Android-приложение U-Net сегментации, которая позволит пользователю настраивать прозрачность каждого из 6 классов в объединенном изображении (united_mask). Вместо захардкоженного выбора класса с максимальной вероятностью, пользователь сможет изменять прозрачность каждого класса с помощью ползунков.

## Текущая реализация
В настоящее время объединенное изображение (united_mask) создается в методе `createUnitedMask` класса `ImageStitcher.kt` с использованием следующей логики:
- Для каждого пикселя выбирается класс с максимальной вероятностью
- Цвет пикселя определяется номером класса
- Нет возможности регулировать прозрачность отдельных классов

## Требования к новой функции

### UI/UX требования
1. Добавить кнопку настроек (с иконкой шестеренки) справа от кнопки предикта на основном экране
2. При нажатии на кнопку настроек открывается новая активность
3. На новой активности:
   - Вверху отображается объединенное изображение (united_mask)
   - В середине 6 ползунков (SeekBar) по одному для каждого класса
   - Каждый ползунок регулирует прозрачность соответствующего класса (от 0% до 100%)
   - При изменении ползунка изображение обновляется в реальном времени
   - Внизу кнопка для сохранения настроенного изображения
   - Сохраненное изображение должно иметь имя формата `united_mask_i.png`, где i - порядковый номер

### Технические требования
1. Каждый ползунок должен управлять альфа-каналом соответствующего класса
2. При нулевой прозрачности класс должен быть полностью прозрачным
3. При 100% прозрачности класс должен быть видимым
4. Нужно реализовать наложение классов с учетом их прозрачности
5. Сохранение изображения должно происходить в ту же директорию, что и оригинальные результаты

## Применение принципов SOLID

### Принцип единственной ответственности (SRP)
- `TransparencySettingsActivity` - отвечает только за отображение UI и взаимодействие с пользователем
- `TransparencyImageProcessor` - отвечает исключительно за обработку изображений и наложение масок
- `TransparencySettingsRepository` - отвечает за сохранение изображений

### Принцип открытости/закрытости (OCP)
- Создать интерфейсы для обработки изображений и наложения масок, что позволит легко добавлять новые алгоритмы
- Использовать параметры конфигурации, позволяющие изменять поведение без модификации кода

### Принцип подстановки Лисков (LSP)
- Все реализации интерфейсов обработки изображений должны быть взаимозаменяемыми
- Наследуемые классы должны дополнять, а не изменять базовое поведение

### Принцип разделения интерфейсов (ISP)
- Создать узкоспециализированные интерфейсы: `IImageOverlayProcessor`, `ITransparencyImageSaver`, `ITransparencyStateProvider`
- Каждый интерфейс должен содержать минимально необходимый набор методов

### Принцип инверсии зависимостей (DIP)
- Активности должны зависеть от абстракций, а не от конкретных реализаций
- Использовать внедрение зависимостей для слабой связанности компонентов

## План реализации

### Этап 1: Создание интерфейсов и моделей данных
- Определить интерфейсы для обработки изображений с прозрачностью
- Создать модель данных для хранения состояния прозракости
- Создать интерфейсы репозиториев

### Этап 2: Реализация бизнес-логики
- Создать класс `TransparencyImageProcessor` для обработки изображений с учетом прозракости
- Реализовать алгоритм наложения масок с альфа-каналом
- Создать репозиторий для сохранения изображений

### Этап 3: Создание компонентов UI
- Создать `TransparencySettingsActivity`
- Создать макет `activity_transparency_settings.xml`
- Реализовать обработку событий ползунков

### Этап 4: Интеграция с основным экраном
- Добавить кнопку настроек на MainActivity
- Реализовать передачу текущего изображения в новую активность
- Обеспечить правильное отображение текущего объединенного изображения

### Этап 5: Реализация сохранения
- Реализовать функцию сохранения отредактированного изображения
- Реализовать генерацию уникальных имен файлов

## Необходимые компоненты

### Интерфейсы
- `IImageOverlayProcessor` - для обработки наложения масок
- `ITransparencyImageSaver` - для сохранения изображений
- `ITransparencyStateProvider` - для управления состоянием прозракости

### Классы
- `TransparencyState` - модель данных для состояния прозракости
- `TransparencyImageProcessor` - реализация обработки изображений
- `TransparencySettingsActivity` - активность настроек
- `TransparencySettingsRepository` - репозиторий для сохранения

### Макеты
- `activity_transparency_settings.xml`

## Потенциальные проблемы
1. Производительность: Обновление изображения в реальном времени может быть ресурсоемким - решение: использовать оптимизированные алгоритмы и возможно фоновую обработку
2. Память: Хранение промежуточных изображений может потреблять много памяти - решение: использовать эффективное управление памятью
3. Передача изображения между активностями: Нужно учитывать ограничения на передачу Bitmap через Intent - решение: использовать передачу пути к файлу и загрузку по необходимости
