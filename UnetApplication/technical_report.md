# Технический отчет по проекту UnetClassApplication

## Стек технологий и библиотеки

- **Язык программирования**: Python
- **Основные фреймворки для глубокого обучения**:
  - PyTorch (указан в requirements.txt без версии, но используется в коде)
  - segmentation_models_pytorch (для U-Net на основе ResNet, используется в архитектуре Lars76_unet)
- **Библиотеки для работы с изображениями**:
  - OpenCV (cv2) - используется в prepare_data.py
  - scikit-image (skimage) - для чтения изображений и работы с цветовыми пространствами
  - Также используется в коде TorchVision (указан в requirements.txt)
- **Библиотека для диффузионной модели**: 
  - В проекте упоминается "diffusion" как режим работы, но явной зависимости от Hugging Face Diffusers не найдено. В коде есть заготовки для реализации диффузии, но полноценной реализации диффузионного шедулера нет.

## Детали реализации обучения

- **Оптимизатор**: В конфигурационных файлах указывается "Adam", но точная реализация функции getOptimizerByName не найдена в коде. На основе контекста, вероятно используется torch.optim.Adam.
- **Планировщик скорости обучения**: В конфигурационных файлах встречается "lr_scheduler_200", что указывает на использование планировщика, но детали реализации не ясны.
- **Размер батча и количество эпох**: 
  - batch_size: 7 (в конфигурационном файле)
  - epochs: 200 (в конфигурационном файле)
- **Аугментация данных**: 
  - Параметры аугментации заданы в конфигурационных файлах:
    - rotation_range: 7
    - width_shift_range: 0.05
    - height_shift_range: 0.05
    - zoom_range: 0.1
    - horizontal_flip: true
    - vertical_flip: true
    - noise_limit: 3
    - rotate_90: 0.5
  - Реализация аугментаций не найдена в явном виде, предполагается использование самописных функций

## Аппаратная часть

- **Использование CUDA/GPU**: 
  - В коде присутствует проверка на доступность CUDA: `torch.cuda.is_available()`
  - В конфигурационных файлах указан "device": "cuda"
  - В prepare_data.py встречается `to("cuda")`
- **Mixed Precision**: 
  - В коде нет явного использования mixed precision (fp16/bf16) или torch.cuda.amp

## Детали реализации моделей

- **Tiny-U-Net (Tiny_unet_v3)**: 
  - Архитектура: channels 32->32->64->128->256 (в down path)
  - Да, в блоках DoubleConv используется `torch.nn.BatchNorm2d`
  - В коде архитектура определена как:
    ```python
    self.init = (DoubleConv(n_channels, 32))
    self.down1 = (Down(32, 32))
    self.down2 = (Down(32, 64))
    self.down3 = (Down(64, 128))
    self.dropout = nn.Dropout(0.5)
    factor = 2 if bilinear else 1
    self.down4 = (Down(128, 256 // factor))
    ```
- **Диффузионная модель**:
  - В коде есть заготовки для диффузионной модели (в prepare_data.py), но полноценной реализации UNet2DModel и Scheduler (DDPMScheduler, DDIMScheduler) не найдено
  - В конфигурационных файлах упоминается задача диффузии, но конкретные параметры Scheduler'а отсутствуют

## Реализация геометрического синтеза

- В проекте не найдена реализация геометрического синтеза примитивов (линий, сплайнов)
- Использование OpenCV для рисования геометрических форм не обнаружено
- Проект фокусируется на семантической сегментации, а не на генерации геометрических форм

Важно отметить, что функция `getOptimizerByName` используется в коде, но её реализация не найдена в текущих файлах исходного кода, что может указывать на отсутствующую зависимость или незавершенный код.
